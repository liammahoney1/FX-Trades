# FX-142 — Entitled FX exception investigation view

Status: Approved synthetic demo epic

## Product decision

Build the smallest safe vertical slice that aggregates existing exception evidence for an entitled operations analyst. The slice may show lifecycle state, prioritize evidence, and recommend a next investigation step. It may not remediate a trade, change trade state, or communicate externally.

## Target user

An institutional FX operations analyst investigating a failed or delayed trade.

## Functional requirements

1. Retrieve a synthetic trade by trade ID.
2. Enforce existing account and region entitlements before returning trade information.
3. Return lifecycle state and exception evidence ordered by investigation priority.
4. Include source, source record ID, and timestamp for each evidence item.
5. Return a derived recommended investigation step separately from source facts.

## Acceptance criteria

### AC1 — entitled investigation

Given an analyst entitled to the trade's account and region, when the analyst requests an investigation view, then the response contains the trade ID, currency pair, lifecycle state, ordered evidence, and a recommended investigation step.

### AC2 — evidence provenance and ordering

Given more than one evidence item, when the view is built, then higher-severity actionable exception evidence appears before informational lifecycle evidence, and every item includes its source, source record ID, and timestamp.

### AC3 — authorization denial

Given an analyst who lacks either the account or regional entitlement, when the analyst requests the view, then access is denied without disclosing client, trade, or evidence details.

### AC4 — unknown trade

Given an unknown trade ID, when an analyst requests the view, then the service returns the repository's existing not-found behavior.

### AC5 — excluded actions

Given any investigation view request, then the service performs no remediation, trade-state mutation, or client communication.

## Non-functional and control requirements

- Standard library only for this demonstration.
- Preserve the existing authorization boundary.
- Derived recommendations must be identifiable as derived output.
- Production audit logging remains a documented follow-up and is not silently simulated.

## Out of scope

- Root-cause confirmation
- Automated remediation
- Trade-state changes
- Client communications
- New entitlement models
- Production UI and deployment

## Open question

The approved evidence does not establish the production severity taxonomy. The demo may use the repository's synthetic severity field while recording this as a production validation item.
